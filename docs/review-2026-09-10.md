# Recording and interface review, 10 September 2026

GPT-5.6 Terra reviewed recording and scheduling; GPT-5.6 Luna independently reviewed evidence, storage, and security. The main agent reviewed and integrated their changes and redesigned the interface.

## Confirmed code defects

- TaskManager preserves Android task options between APK updates. The old start path returned immediately for an active task, so an installed hourly build could still have an older fast registration. Active foreground resume now checks persisted options, reapplies the hourly schedule when needed, and appends a signed configuration event. Start, Stop, and reconciliation share a lifecycle queue. No existing observation is rewritten or removed.
- Overlapping background callbacks could overwrite the last measurement metadata with an older timestamp, affecting later gap detection. Callbacks now serialize within a runtime, and SQLite updates the timestamp monotonically across writers.
- Stop now marks recording inactive before unregistering, checks that state during queued callback processing, and does not mark recording active again if only the subsequent journal append fails.

The screenshots demonstrate frequent new measurements. They do not include the persisted task options, so device confirmation is still required to establish that the identified upgrade bug explains this particular session.

## Interface changes

The latest observation shows the device's current local timezone, local date and time, and the original UTC instant. Timezone conversion affects display only. The device screen shows the installed app version, key protection, and full signing-key fingerprint.

Coverage separates location readings from the total signed event count. The existing gap records remain intact. The explanation states that a separation over two minutes counts as a gap, including planned hourly spacing. Gap counts are not crash counts and do not establish continuous coverage.

Optional address lookup requires an explicit confirmation for each selected observation. The OS geocoding provider may receive the selected coordinates and require internet. The result is approximate, held only in UI memory, and never added to signed evidence. Recording does not depend on geocoding. No real coordinates were sent during development verification.

Outfit fonts are bundled in the APK, including license notices. The app supports system, light, and dark appearance. Manual appearance selection applies to the current app session.

## Android interval readback correction

A subsequent phone screenshot showed an unavailable interval after reconciliation. Expo TaskManager 57.0.16 `mapToBundle` omits Java Long values, while Expo Location declares `timeInterval` as Long. The app now applies a narrowly scoped, idempotent postinstall patch to preserve Long values. The patch also accepts Number when restoring the interval from a persisted map, since JSON may deserialize 3,600,000 as Integer. Patch application fails if the expected upstream source changes, requiring review during upgrades. CI's npm install applies it before native compilation.

The UI now distinguishes an unavailable interval from a known mismatch. UTC display also consistently includes its label for observation timestamps with milliseconds. The new native patch requires rebuilding and installing the APK; JavaScript bundling alone does not validate the native fix on a phone.
